LLM 如何识别图片

LLM 没有眼睛——它只是把图片「翻译」成了 token（一小块信息的数字代号）： 切块 Patch → ViT 读出每块特征 → Projector 翻译成「文字语」 → 和文字 token 排成一队，统一理解、逐字生成。

01四步到底在干嘛（大白话版）

  • ① 切块：大图切成 9 小块——一次只看一小块，看得清、算得动（实际如 14×14 像素/块，一张 224×224 的图 → 256 块）
  • ② ViT「读」每块：这块是橙色的圆、那块是紫色的三角……每块被压缩成一串数字（向量）——这串数字就是这块内容的「特征代号」
  • ③ Projector 当换算器：LLM 只认识词表里约定的数字（「圆」=[0.5, 0.1, …]），ViT 算出的是词表里没有的「野生数字」→ 直接喂等于乱码；Projector 把数字换算到对应词汇附近（贴着「圆」「橙」），LLM 一读就懂：右上有个橙色的圆
  • ④ 排队进 LLM：9 个图片 token + 问题的文字 token 排成一排；LLM 眼里没有「图」和「字」的区别——都是数字，一起算关联，像接龙一样逐字蹦出答案

02关键认知

  • LLM 没有眼睛：看图和读文是一回事——都是处理一串数字（token）；区别只在「代号」的来路：文字的代号查词表就有，图片的代号要靠 ViT 从像素里算出来
  • 为什么非要 Projector：LLM 词表里的每串数字都是预训练定死的，它只认这套；ViT 的数字是另一套体系。Projector 就是两套数字的「汇率」——用千万级「图片 ↔ 文字描述」对练出来，换算准了，LLM 才能把图片「听」成一段描述
  • 两个常见误会：① 是「换算」不是「查字典」——图片块的向量有无穷多种、无典可查，是矩阵乘法直接算到「圆」「橙」附近；② 换算结果也不是词表里的某个词条，而是词向量空间里贴着「圆」「橙」的「新点」——LLM 靠空间位置读懂它；且它是视觉语义特征（不是像素 token，像素早已被 ViT 读成了语义）
  • 图片很费 token：一张图动辄几百上千个视觉 token（如 LLaVA 每张 576 个）→ 多图、高清图明显更慢更贵
  • 细节会丢：patch 切得越粗越省 token，但小字、小物体容易看不清 → 细粒度场景需要更高分辨率或动态切块（深入：LLM 如何识别图片中的文字 →）
  • 流程里为什么没有 OCR：LLM 识图是端到端的——图里的文字和猫毛纹理一样，走同一套 patch → ViT → 训练流程被「看」懂，没有独立的文字识别模块；OCR 只出现在两处：① 专用识别系统（票据录入，上一代方案）② Agent 工具链（LLM 调 OCR 工具先提取文字，再读文本）
  • 训练分两阶段：先冻结 LLM、用图文对数据练 Projector（对齐两个空间），再指令微调端到端练理解能力

03代表方案对比

方案视觉编码器对齐方式特点
LLaVA（开源经典） CLIP ViT MLP Projector 结构就是上图，理解多模态原理的最佳样本
GPT-4o / Gemini 原生多模态 端到端联合训练 图、文、音频统一 token 化，出生就是多模态
Qwen-VL ViT（高分辨率） 位置感知适配层 支持 grounding：能框出物体在图中的位置
面试一句话：LLM 识别图片 = 切块（Patch）+ ViT 编码 + Projector 对齐，把图片翻译成几百个视觉 token，再和问题文本拼成同一序列喂进 LLM——对 LLM 而言，「看图」和「读文」没有任何区别，都是 token 序列。
