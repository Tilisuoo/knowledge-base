LLM 如何识别图片中的文字（OCR）

先澄清：LLM 识字用的不是 OCR 技术——它和看猫看山走的是同一条端到端流程，「OCR」在这里只是「识别图中文字」的通俗说法。 通用流程遇到小字会翻车：字比 patch 还小，被拦腰切碎、糊成碎片。 识字靠的是两个补丁——动态高清切块保证字形完整， 再加海量「字形 ↔ 字符」训练建立形状到文字的关联。

01为什么通用流程遇到文字会翻车

  • patch 是固定大小的（如 14×14 像素）：一行 20px 高的字，横向被切、纵向拦腰，每个 patch 只剩几笔碎片
  • ViT 再强也编不出「没看清」的字：token 里信息不足，模型只能瞎猜 → 这就是文字场景常见的「幻觉乱码」
  • 字越小、排版越密（文档、票据、表格），翻车越狠

02补丁一：动态高清切块

  • 思路：图片多大就给多少 token，不再一刀切压缩到低分辨率
  • Qwen2-VL：Naive Dynamic Resolution——按原图分辨率切块，token 数量随图大小伸缩
  • InternVL / LLaVA-NeXT：大图切成多张 448×448 子图分别编码，再加一张全局缩略图保留整体
  • 效果：一个字从「半个 patch」变成「4+ 个 patch」，笔画完整 → token 信息足够

03补丁二：识字训练（字形 → 字符的关联）

  • 字形也是像素模式：「出」字 5 笔在 patch 里是稳定的视觉模式，跟猫毛纹理没有本质区别
  • 千万级图文对（文档截图、街景招牌、手写体……）让模型建立关联：这种 token 模式 = 这个字
  • 阅读顺序从哪来：训练标签按「从左到右、从上到下」标注 + 2D 位置编码保留空间信息 → 模型按顺序吐字，而不是随机蹦字

04追问：一个字占多个 patch，怎么「拼」回去

  • 没有「合并」这一步：模型从不把几块碎片拼回整字——就像 subword 分词（un + believ + able）也不需要先拼回完整单词
  • ① 位置编码：每个 token 自带「第几行第几列」的坐标，4 块碎片的空间关系不丢
  • ② 多层自注意力：相邻 token 互相「看」，几层 Transformer 之后，每块都融合了整字的信息（感受野覆盖整个字甚至整行）
  • ③ 训练强化：监督信号是完整文字，模型被迫学会「这几块凑在一起 = 出」
  • 类比：人看拼图也不用真拼起来——眼睛扫过几块，就知道是什么图案

05传统 OCR vs LLM 识字

传统 OCR（DBNet + CRNN）多模态 LLM
流程 先检测文字框 → 逐框识别，两阶段 端到端：看图直接输出文字/答案
优势 小字密集文档稳、快、成本低 识字 + 理解一体：能直接答「这家店几点关门」
短板 只转文字，不懂意思 看不清会「脑补」（幻觉），超长文档费 token
适用 票据、证件、批量录入 问答式理解、图表、手写 + 语义场景
面试一句话：LLM 识字 = 通用识图流程 + 两个补丁——①动态高清切块，保证字形完整不被 patch 切碎；②海量「字形 ↔ 文字」训练对，建立形状到字符的关联并按阅读顺序输出。但看不清时它会「脑补」，票据证件等关键场景仍要用专用 OCR 兜底。
