一主一从（读写分离）

① 写请求全部路由到主库；② 读请求路由到从库； 主库数据经 ③④⑤ Binlog 复制链路（dump 推送 → IO 线程 → Relay Log → SQL 线程回放）同步到从库。

01数据流

  • ① 写请求：INSERT / UPDATE / DELETE（及事务内的读）→ 全部路由到 Master 主库
  • ② 读请求：SELECT → 路由到 Slave 从库（一从时无负载均衡，独占读流量）
  • ③④⑤ 复制链路：Master 的 dump 线程推送 Binlog → Slave IO 线程写入 Relay Log → SQL 线程回放，最终一致

02特点

  • 优点：架构最简单、成本低、单点写入无冲突，读流量全部卸载到从库
  • 缺点：主库是单点——宕机后写入中断，需配合 MHA / Orchestrator 手动或半自动切换；写能力无法扩展
  • 适用：中小规模、读多写少、写入量单个主库可承载的业务
核心权衡：用「主库单点」换取「读流量卸载 + 极简运维」；写入高可用需求出现后，升级为 双主双从。
