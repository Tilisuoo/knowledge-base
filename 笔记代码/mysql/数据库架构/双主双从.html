双主双从（读写分离）

① 写请求只落 Master-1（单点写）；② 读请求分摊到两个从库； ③ 双主双向复制互为主从热备；④ 主从复制同步到各自从库。

01数据流

  • ① 写请求：只发往 Master-1（Active）——双主架构也坚持单点写，避免双向写冲突
  • ② 读请求：沿两侧链路下发到 Slave-1 / Slave-2，按负载均衡分摊
  • ③ 双向复制：Master-1 ⇄ Master-2 互为主从，M2 实时热备；M1 宕机后经 Keepalived + VIP 漂移（或 MHA）切到 M2，写入秒级恢复
  • ④ 主从复制：M1 → S1、M2 → S2，各自走 Binlog（IO 线程 → Relay Log → SQL 线程回放）

02特点

  • 优点：主库高可用（写不中断）、读能力双倍扩展；M2 平时还可承担备份、DDL 演练等任务
  • 缺点：架构与运维复杂度翻倍；双向复制必须防冲突——自增 ID 错位（auto_increment_increment=2 + 各自 offset）、严禁双写、防脑裂
  • 适用：对写入可用性要求高的核心业务库
核心权衡：用「翻倍的服务器 + 复杂度」换取「写入高可用」；写入量不大、可容忍分钟级切换的业务，用 一主一从 更划算。
