布隆过滤器（Bloom Filter）

一个位数组 + 多个哈希函数，用极小内存判断「元素是否可能存在」： 添加时把 k 个哈希位置 1；查询时 k 位全 1 才算「可能在」（可能误判）， 只要有一位是 0 就是「一定不存在」（绝不误杀）。

01核心原理

  • 添加：元素经过 k 个哈希函数算出 k 个位置，把位数组对应位置置 1
  • 查询：同样算 k 个位置——全是 1 → 「可能存在」（可能误判）；有一个 0 → 「一定不存在」（绝不误杀）
  • 误判根源：位数组只存 0/1，不同元素的哈希位置会重叠「拼车」，查询时无法区分这些位是被谁占的
  • 两大特性：① 内存极小（不存元素本身，只存 bit）；② 不支持删除——把某位改回 0 可能误删其他元素（要删除用「计数布隆过滤器」，每位换成计数器）

02关键参数与权衡

  • 误判率公式：约 (1 − e^(−kn/m))^k，n=元素个数，m=位数组长度，k=哈希函数个数
  • 调参方向：位数组越大、哈希函数个数适中（通常 k = m/n × ln2），误判率越低；1% 误判率下每个元素约需 9.6 bit
  • 容量预估最重要：实际元素超过预估 n，误判率会指数级飙升 → 生产上按业务峰值预估并留 buffer，或定期重建

03典型应用场景

场景布隆过滤器挡的是什么
缓存穿透（最经典） 恶意请求不存在的 key，把不存在的 key 提前布隆，查询前先过布隆——「一定不存在」直接拦截，不打缓存和 DB
去重（爬虫 / 推荐） 判断 URL 是否已爬过、内容是否已推荐过，海量数据下比 Set 省内存几个数量级
垃圾邮件 / 黑名单 快速判断发件人是否在黑名单，「一定不在」直接放行
大文件分块去重 网盘秒传：先布隆判断文件块是否已存在，避免重复上传存储
面试一句话：布隆过滤器 = 位数组 + k 个哈希，用「可能存在 / 一定不存在」换极小内存；没有 false negative，只有 false positive；经典用途是挡缓存穿透，调参核心是容量预估，要删除就用计数布隆过滤器。
